## 7. Known defects and missing features

1. **No administrative review/resolution workflow.** The atomic protocol can legitimately reach
   `INCONSISTENT_HISTORY`, `BINDING_CONFLICT`, `GUARD_CONFLICT`, yet the only product response is
   "contact admin" and the admin workspace cannot resolve it. Evidence: status route guidance,
   admin routes limited to `/admin` and `/admin/users`.
2. **No shift-creation UI.** Shifts can only be created through the API/scripts. A production
   supervisor cannot start the daily cycle from the product.
3. **Generated dirs poison build and lint.** `tsconfig.json` includes `**/*.ts` plus auto-added
   `.next-*` entries; stale/partial dev type files fail `next build` type-check. ESLint ignores
   only `.next/**`. Clean checkout builds; a workspace with several NEXT_DIST_DIR values does not.
4. **Missing Firestore composite index** for the notification inbox query and no indexes file.
5. **Notifications incomplete for production**: functions undeployed, FCM unverified, client flag
   not documented, no supervisor inbox, no monitoring.
6. **Admin lifecycle gaps**: no revocation UI despite domain code; no password reset.
7. **Orphaned/one-sided surfaces**: technician-pairs page not in nav; task reject/reassign,
   shift recover-expired, v2 finalize/readiness have no UI; legacy gate-off acceptance panel
   stays stale after success.
8. **No audit-log or operational-report reader**; print-only reporting.
9. **Usability**: ambient "Primary Technician" label; dead bell next to a live Notifications nav
   entry; duplicate `APP_ORIGIN`; README boilerplate.
10. **Verification limits**: mobile layouts not exercised (no resize tooling); tasks, admin
    account lifecycle, v1 handover, password change and shift completion remain unverified in
    the browser.

## 10. Verdict

The atomic equal-technician handover core is **product-ready for a controlled staging pilot**:
acceptance, guard finalization, exceptional closure, gate-off fallback, replay refusal,
authorization boundaries and personal attendance were all verified with fresh reproducible
evidence. The application as a whole is **not yet product-ready**: it cannot create a shift
in-product, cannot resolve an administrative-review state, has no audit/reporting read surface,
and its notifications and build configuration are incomplete for production. The P0 list above
is the minimum before any real operational use.
